# Contributing to EmberBoard

EmberBoard keeps the original Dev_Profiles spirit — fork, add yourself, open a PR, get merged — but profile data is separated from the UI so the wall can evolve without contributors editing HTML.

## Add your profile

1. Fork this repository.
2. Create `data/profiles/<your-github-handle>.json` using `data/profiles/_TEMPLATE.json`.
3. Keep your `github` field equal to your real GitHub handle.
4. Add 1–12 skills. Optional fields such as name, role, avatar, links, projects, and building can be included when useful.
5. Commit and push your branch.
6. Open a pull request into `main`.
7. The `Validate profiles` workflow checks your file. After merge, `Deploy EmberBoard` rebuilds the manifest and publishes GitHub Pages.

### Contributor order

Your profile is automatically placed at the **front of the wall** based on `joinedAt`. Newer contributors appear before older contributors; you never need to touch the HTML or reorder other profiles.

### Important

Do **not** edit `index.html` to add a profile. Do **not** add yourself to `data/profiles.json`; that file is generated by `scripts/build-data.mjs`.

### Example

```json
{
  "name": "Your Name",
  "github": "your-handle",
  "role": "Frontend Engineer",
  "avatar": "https://github.com/your-handle.png?size=160",
  "bio": "I make fast interfaces and ship open-source tools.",
  "skills": ["TypeScript", "React", "CSS", "Open Source"],
  "building": "a component library",
  "links": {
    "GitHub": "https://github.com/your-handle",
    "LinkedIn": "https://www.linkedin.com/in/your-handle/"
  },
  "projects": [
    {"name": "My Project", "url": "https://github.com/your-handle/my-project", "kind": "Project"}
  ]
}
```

## Design principle

The UI is intentionally neumorphic, orange/grey/white, tactile and motion-heavy. New UI work should preserve keyboard access, mobile responsiveness and `prefers-reduced-motion` support.


## Display order

- The home page shows **only the 6 newest contributors**, sorted by `joinedAt` descending.
- The `Contributors` page shows the **complete contributor directory**.
- New merged profiles automatically appear at the front of the home page.


Minimum payload:

```json
{
  "github": "your-handle",
  "bio": "A short description of what you build or care about.",
  "skills": ["JavaScript", "Open Source", "Your Skill"]
}
```

The build pipeline validates the file, fills safe defaults, records the board join date from the profile-file Git history when available, and enriches public GitHub metadata during GitHub Actions. Generated metadata is never required from contributors.

### What is enriched automatically

Public avatar, GitHub URL, display name, follower count, public repository count, approximate repository-star total, top languages, recent public-activity pulse, activity streak, a 28-day public-activity matrix, Contribution Aura, and an illustrative rarity tier. Public activity is limited by GitHub's public-events API window; the UI labels it as public activity rather than private contribution history.

### Pull request flow

1. Fork the repository.
2. Create `data/profiles/<github-handle>.json`.
3. Run `npm run validate` locally.
4. Commit and push your branch.
5. Open a Pull Request.
6. CI validates the profile and the merge/deploy workflow rebuilds the wall.

The homepage shows the six newest contributors. The Contributors page contains the complete directory.
